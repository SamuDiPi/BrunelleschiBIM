# ADR 0008: 3D view technology

Status: accepted (2026-11-16) by the owner, as recommended below.

## Context

ADR 0005 deferred the 3D view to the first interface milestone. M8 compared candidates on
the M7 house and on a generated model of 480 walls and 240 doors (12,480 triangles).
Scripts: `spikes/m8/`. Machine: the owner's laptop (Intel integrated graphics for
OpenGL; NVIDIA RTX 2000 Ada via Vulkan for wgpu). Every probe rendered off screen (no
window) and its image was looked at.

## Excluded before measuring

- **Qt Quick 3D**: available only under GPLv3 or a commercial licence ("Qt Quick 3D is
  available under the commercial license from The Qt Company. In addition, it is
  available under the GNU General Public License, version 3",
  https://doc.qt.io/qt-6/qtquick3d-index.html). Shipping it would make our executable
  GPL; the project is LGPL (ADR 0004).
- **Qt 3D**: deprecated since Qt 6.8 and removed from the official release
  configuration (Qt 6.8 "What's New"; Qt development mailing list, March 2024).

## Measurements

Geometry is triangulated by IfcOpenShell from our IFC export in all cases (see "Common
finding" below).

| | A. PyVista 0.49 / VTK 9.7 | B. Own OpenGL 3.3 in Qt | C. pygfx 0.17 / wgpu 0.33 |
|---|---|---|---|
| Licence | BSD-3 | ours + PyOpenGL (BSD) | BSD-2 |
| Added install size | +367 MB (VTK alone ~296 MB) | +15 MB | +21 MB |
| Import time | 0.97 s | ~0 | 0.38 s |
| Scene build, large model | 0.08 s (merged mesh) | 0.04 s | 1.3 s; 4.6 s on first use (GPU and shader setup) |
| Frame, large model | 0.3 ms (merged mesh); 22 ms with 720 separate actors | 0.8 ms | 32 ms off screen (includes reading the image back) |
| Picking an element | 3 ms, correct | 1 ms, correct | 2 ms, correct |
| What we must write | little: camera, picking, clipping exist | camera control, picking (done in the probe, ~200 lines), edges, highlight, later section boxes | camera control helpers exist; API still 0.x |
| Driver path | OpenGL | OpenGL | Vulkan / D3D12 / Metal |

All three rendered the house correctly (mitred corners, door and window in their
openings).

## Common finding: the mesh source matters more than the viewer

Exporting the large model to IFC takes 2.8 s and triangulating it 4.1 s on one thread,
0.73 s on 22 threads. An interactive view must not export and triangulate the whole model
after each edit: it keeps a mesh per element and re-triangulates only changed elements
(the `regen/` change detection already knows which). If that is still too slow, walls
and openings are simple enough to mesh directly from our footprints without IFC.

## Recommendation: B, our own OpenGL view behind a small interface

- Our needs for the next phases are narrow: shaded solids, edges, selection highlight,
  orbit/pan/zoom, later a section box. VTK's strengths (scientific visualisation, filters,
  volume rendering) are mostly unused, and it would double the executable (from about
  270 MB to about 570 MB) and add a hard packaging dependency.
- B was the fastest in every measurement here and the picking already works.
- pygfx is attractive technically, but its API is pre-1.0, its first-use cost is
  seconds, and Vulkan/D3D12 on office PCs with old drivers is less proven than OpenGL.
- The view sits behind our own `Viewport` interface (set meshes, set camera, pick,
  highlight). If needs outgrow it, VTK can replace the backend without touching the rest
  of the interface.

Costs accepted with B: camera interaction, edges and section tools are our code to
write and test (an estimated one or two extra days in M12 compared with VTK); OpenGL 3.3
core is required (any PC of the last ten years; the probe ran on Intel integrated
graphics).

## Amendment (2026-11-16, M12): meshes are ours, not from the IFC export

The M8 finding ("the mesh source matters more than the viewer") was acted on: the 3D view
does not export IFC and triangulate it. `brunelleschi.geometry.solids` builds each wall as
the prism of its joined footprint, sliced across at its openings, and doors and windows
as simple boxes; `brunelleschi.regen.meshes` caches them per element. Every element's
volume equals IfcOpenShell's evaluation of the IFC export to 1e-14 m3 (tested). On the
480-wall model: 0.54 s for all meshes, 0.13 s after editing one wall, 0.73 s after
moving a level that every wall uses. The renderer uses Qt's OpenGL classes only; PyOpenGL
is not a dependency. IFC references (M13) will use IfcOpenShell's triangulation, behind
the same scene.
